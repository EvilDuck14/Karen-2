# Karen 2.0.0

> *"Congratulations on completing the rigorous Training Wheels Protocol and gaining access to your suit’s full capabilities... Would you like me to engage Enhanced Combat Mode?"* - Karen

Karen is named after Spider-Man's virtual assistant in *Spider-Man: Homecoming*, who advised Peter in strategy and combat. This tool is designed to quickly, easily, and accurately analyse Spider-Man's combos in Marvel Rivals. 

Karen is designed to be used as a Discord bot to aid with labbing and communication of combos / ideas. This means that users don't have to concern themselves with installing anything - just join a [Discord server with the bot](https://discord.gg/5bFRxaCzCS), or add Karen to your own server using the [invite link](#install-local-discord).

## <br> Installation

If you're already in a Discord server which has Karen added, there's no need to install anything - you can start using commands in the designated channels right away! Jump to the [section on usage](#commands) for a detailed explanation of how to use these commands to their fullest potential.

<a id="install-discord"></a>
### Adding to Discord

If you want to add Karen to your Discord server, you can do it using [this link](https://discord.com/oauth2/authorize?client_id=1343900821405827072&permissions=18432&integration_type=0&scope=bot). Karen requests minimal premissions to function, but it does need to be able to read and send messages to function.

<a id="install-data"></a>
### Data Sharing

Karen keeps a tally of how many times each combo has been evaluated to help understand how it is being used. It also knows how many servers it is running on. Karen **does not** read messages in your server besides commands (but as a PSA, Discord is fundamentally a public platform, and you should never consider your messages in any server to be truly private).

## <br> Commands

All commands are accessed using a `!` followed by the name of the command and any associated arguments. 
Examples will be provided for each command.

<a id="commands-eval"></a>
### Evaluate

The `!eval` command takes a sequence of actions, then evaluates the combo by calculating metrics such as time taken and damage dealt. 
For example, to evaluate a Bread & Butter Long Plink, one might use the command `!eval tracer > goht > uppercut > swing whiff > tracer > overhead`.
This same command could be written using the short form `!eval tGuwto`, or by using the combo name `!eval bnb long plink`.
For more information on how to write a combo that Karen will understand, see the section on [combo comprehension](#comprehension).

The user can provide multiple combos separated by commas, which will trigger comparison mode.
For example, to compare a Bread & Butter Long Plink to a Slam Combo, one might use the command `!eval tGuwto, totu`.

Parameters can be included in combo commands using `--[parameter name]`. 
For example, to see the ult charge generated by the Bread & Butter Long Plink, one could use the command `!eval tGuwto --ult`. 
If no parameters are given, the user's [preferences](#commands-prefs) will be used.
For a complete description of existing parameters, see the section on [parameters](#params).

<a id="commands-tech"></a>
### Tech

The `!tech` command takes the name of a tech, and provides a description for that tech.
For some techs, a relevant YouTube video is also linked.
For example, if a user wanted to learn about bunnyhopping, they could use the command `!tech bhop`.
For a list of all techs, one can use `!list techs`.

<a id="commands-list"></a>
### List

The `!list` command lets the user access useful information in Karen's database.
A list of all actions that are recognised by the [eval command](#commands-eval) is given by `!list actions`.
One can also use `list combos` for a list of all named combos, `!list techs` for all techs recognised by the [tech command](#commands-tech), and `!list params` for a list of all [parameters](#params). 

<a id="commands-prefs"></a>
### Preferences

The `!prefs` command allows a user to set a default list of [parameters](#params), which will be used whenever the [eval command](#commands-eval) is called without any parameters given.
For example, a user can input `!prefs --a` so that their default behaviour is [advanced mode](#params-a).

If any parameters are explicitly given to a command, the user's preferences are ignored. This means that a user can use the default set of parameters by giving an empty parameter, ie. `!eval tGuwto --`.

<a id="commands-help"></a>
### Help

The `!help` command will give a list of all recognised commands and link to this documentation. More information can be found on any command using `!help [command]`.

## <br> Combo Comprehension

To make Karen as intuitive and efficient to use as possible, many ways of describing the same combo are supported. There are three broad categories of notation:
- Long-form: `tracer > get over here targetting > uppercut`
- Short-form: `tGu`
- Named sequences: `bread and butter`

A user can mix and match notations, and Karen will do its best to interpret what is meant. Regardless of the user's chosen notation, Karen will always output the full long-form sequence with its output so that the user can verify that their input was understood correctly.

<a id="comprehension-actions"></a>
### Individual Actions

For individual actions, the name of the action can be used (eg. `tracer`) or the short form symbol can be used instead (eg. `t`).
For a list of actions (and [early cancels](#comprehension-cancels)/[movestacks](#comprehension-movestacks)) and the associated short form symbols, one can use `!list actions`.

Many actions have several common names, so `cluster` is also understood to mean the same thing as `tracer`, for example.

<a id="comprehension-cancels"></a>
### Early Cancels

To denote cancelling an animation early, one can use `-`.
This same notation is also used to denote a no stick via `a-` (or `autoswing-`).
This is otherwise only usable on melee attacks, as it has no practical function for most actions.
Note that this allows one to burn a stored overhead (so that a punch can be used later), and that cancelling a melee attack early always resets the melee sequence (punch 1 > punch 2 > kick) back to the start.

<a id="comprehension-movestacks"></a>
### Movestacks

Movestacks involve overlapping the animations and/or behaviour of several basic actions simultaneously.
This can be denoted by combining the relevant actions with a `+`.
For example, to denote a FFAmestack, one can use `goht + uppercut` or `G+u`.

<a id="comprehension-sequences"></a>
### Named Sequences

Existing named sequences can be included in evaluations by simply writing their names.
For example, if one wants to evaluate The Opener followed by a long plink, they could write each action `!eval otuwto`, or they could use the sequence names `!eval opener > long plink`.
These named sequences include all named combos (for a list, use `!list combos`), as well as all plink variations, and the unique 2/3 hit sequences. 

<a id="comprehension-mixed"></a>
### Mixed Inputs / Grammar

Short form actions, long form actions, and named sequences can all be included in a single evaluation.
White space is ignored entirely (so `tra cer` will be understood as a tracer).
Actions/names can be manually separated using `>`, but this is optional.

<a id="comprehension-comments"></a>
### Comments

Anything inside of parentheses will be entirely ignored. This means that `!eval tra(overhead)cer` will be parsed as `!eval tracer`, for example. [Parameters](#params) are also ignored if they are inside of the brackets in an eval command.

<a id="comprehension-wait"></a>
### Wait

A combo can involve waiting mid-sequence using square brackets with the wait time inside. 
This can be given in frames (`[30f]`, assuming 60fps) or seconds (`[0.5s]`).

One can also wait after using the upgraded symbiote for a certain number of teather hits.
For example `V[2T]w` will use the upgraded symbiote and then wait for 2 hits of teather damage before proceeding to cancel the teather with a swing whiff.

Finally, one can wait until the web bomb has a certain duration remaining.
For example, `B[20B]pp` will throw the web bomb, wait until 20 frames remain until it explodes, then proceed with two punches (so that the explosion happens between them).
This can mostly be ignored, since the `E` action allows the explosion to be placed manually.

<a id="comprehension-autocorrection"></a>
### Autocorrection

Certain inputs are automatically corrected, such as action sequences which are impossible unless they are interpreted as a movestack.
For example, `punch > goht` is impossible, since the punch procs the tag which is required for get over here (targeting) to be used, so it is automatically corrected to a saporen tech, `punch + goht`.

If a clap is used at the start of a combo, the explosion action is included, and no wait actions are included, Karen automatically calculates how long to wait at the start of the combo to maximise the burst damage (ie. to avoid having to slow down by waiting for the explosion)
This calculation is rough, so the evaluation may still have to wait a few frames for the explosion.

Finally, if an uppercut isn't canceled with a swing whiff when it would make the combo faster, this is automatically inserted (but raises a warning).
This is intended for beginners who forget to weave animation cancels, and can be disabled by using [advanced mode](#params-a).

## <br> Parameters

Each command supports the addition of parameters which allow the user to adjust the format/information presented in the output of the command. A user can save a default set of parameters using the [prefs](#commands-prefs) command.

The "display" parameters affect which metrics are displayed in the evaluation summary.
By default, this includes [time](#params-t), [time from damage](#params-tfd), and [damage](params-d).
If any display parameters are given, then all of the displays that aren't requested are disabled (including the defaults).

<a id=params-a></a>
### Advanced Mode (--a)

Advanced mode stops the combo comprehension from automatically inserting swing whiffs after uppercuts.
This allows advanced users to calculate combos such as `tGutp` instead of Karen assuming a mistake was made and [automatically correcting](#comprehension-autocorrection) it to `tGuwtp`.

<a id=params-b></a>
### Show Breakdown (--b)

This parameter will show a frame-by-frame breakdown of everything that happened internally during the calculation.

<a id=params-n></a>
### No Warnings (--n)

This parameter will stop warnings from being output.
These warnings often highlight large errors with the validity of the requested combo, so this isn't recommended for most users.

<a id=params-t></a>
### Display Time (--t)

Time is displayed in seconds and frames (assuming 60fps).

<a id=params-tfd></a>
### Display Time From Damage (--tfd)

This displays the time taken by the combo from the first to the last tick of damage (not counting the web bomb's 1 damage upon landing).
This is a useful metric as it measures the burst damage of a combo, helping to understand how difficult it is to heal through.
It can also be useful to understand how little time a target has to react if they are caught off guard and don't notice you until you start damaging them.

<a id=params-d></a>
### Display Damage (--d)

This displays damage dealt by the full combo.

<a id=params-dps></a>
### Display DPS (--dps)

Damage per second is another metric of how much burst damage a combo does, and how difficult it is to heal through.
This is calculated using damage divided by the time from the first to last hit of the combo (again, ignoring the web bomb if it preceeds other damage).

<a id=params-ult></a>
### Display Ult Charge Generation (--ult)

This displays the percentage of ult charge that is generated by the combo, which is contributed to by the damage dealt and time taken (passive ult charge generation).
